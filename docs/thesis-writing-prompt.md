# 논문 작성 프롬프트

컨펌(Confirm) 프로젝트로 국문 학위논문을 쓰기 위한 프롬프트 모음이다.
[thesis-format-rules.md](thesis-format-rules.md)(작성 규칙)와 [thesis-toc.md](thesis-toc.md)(목차)를 바탕으로 한다.

## 사용법

1. 이 저장소(`confirm`) 루트에서 Claude Code 세션을 연다. 코드와 문서를 직접 읽어야 하므로 파일 접근이 되는 환경이어야 한다.
2. **공통 프롬프트**를 먼저 보낸다.
3. **장별 프롬프트**를 한 장씩 보내고, 결과를 검토한 뒤 다음 장으로 넘어간다. 논문 전체를 한 번에 쓰게 하지 않는다.
4. `{ }`로 표시된 부분은 직접 채운다.

**권장 작성 순서:** 3장 → 4장 → 5장(실험 설계) → 1장 → 2장 → 6장 → 초록 → 부록 → 최종 검수

설계·구현(3·4장)은 코드에 근거하므로 가장 확실하게 쓸 수 있다. 서론과 결론은 본문이 나온 뒤에 써야 내용이 어긋나지 않는다.

## 1. 공통 프롬프트

````text
너는 학위논문 작성을 돕는 연구 보조자다. 이 저장소에 있는 "컨펌(Confirm)" 프로젝트를 주제로 국문 학위논문을 작성한다.

[참고 문서] 작업 전에 반드시 읽는다.
- docs/thesis-format-rules.md : 학위논문 작성 규칙 (작성순서, 인쇄 규격, 제목 번호 체계)
- docs/thesis-toc.md : 논문 목차 초안과 작성 메모
- CLAUDE.md, README.md : 프로젝트 개요, 기술 스택, API 목록
- backend/src, frontend/src : 실제 구현 코드 (서술의 1차 근거)

[논문 정보]
- 제목: {논문 제목} (미정이면 docs/thesis-toc.md의 가제를 쓴다)
- 본문 언어: 국문
- 목표 분량: 본문 약 {N}쪽 (A4, 11pt, 줄간격 200% 기준 1쪽은 공백 포함 약 900~1,000자로 잡는다)

[구조와 번호]
- 목차는 docs/thesis-toc.md를 따른다. 목차를 바꿔야 하면 먼저 제안하고 내 동의를 받는다.
- 제목 번호는 반드시 1. → 가. → 1) → 가) → (1) → (가) 순서로 쓰고, 단계를 건너뛰지 않는다.
- 하위 항목이 하나뿐이면 나누지 않는다.
- 마크다운 제목 수준은 장 #, 절(가.) ##, 항(1)) ###, 목(가)) #### 으로 하고, 번호는 제목 텍스트에 직접 쓴다. (예: "# 1. 서론", "## 가. 연구 배경")

[문체]
- "~이다", "~하였다" 형의 학술 평서체로 쓴다. 구어체, 과장 표현, 홍보 문구를 쓰지 않는다.
- 주어는 "본 연구", "본 논문", "제안 시스템"으로 쓰고 1인칭(나, 우리)은 쓰지 않는다.
- 개조식 나열보다 문단 서술을 우선한다. 각 장과 절은 그 부분에서 다룰 내용을 소개하는 도입 문단으로 시작한다.
- 전문 용어는 처음 나올 때 "작업 분할 구조(Work Breakdown Structure, WBS)"처럼 쓰고 이후에는 약어를 쓴다. 용어 표기는 논문 전체에서 통일한다.
- 서비스명은 처음에 "컨펌(Confirm)"으로 쓰고 이후에는 "컨펌"으로 쓴다. 화면 표기 "Conf:rm"은 1장 각주에서만 밝힌다.
- 회의 유형은 킥오프, 진도 점검, 이슈 체크, 합의로 쓴다. ("이슈 점검"은 쓰지 않는다.)
- 서술형 인용은 "Hou et al.(2024)에서는"처럼 et al.을 쓴다. 괄호 인용은 "(Hou et al., 2024)"이다.
- 그림·표·식 번호 뒤 조사는 숫자를 읽은 소리의 받침에 맞춘다. (예: [표 2]와, [표 3]과, [표 10]과)

[사실 근거] 가장 중요한 규칙이다.
- 시스템에 대한 서술은 저장소의 코드와 문서로 확인한 내용만 쓴다.
- 구현되지 않았거나 비활성화된 기능을 구현된 것처럼 쓰지 않는다. 현재 확인된 항목은 다음과 같다.
  - 실시간 STT 체크리스트 검증: 코드가 주석 처리됨 → 미구현, 향후 연구로 다룬다
  - Naver Works·Notion 연동: API 비활성화 → 미구현, 향후 연구로 다룬다
  - LLM: 현재 Gemini만 동작하고 Claude 호출 경로는 주석 처리됨
  - 문서 분석: OCR이 아니라 pdf-parse로 PDF 텍스트를 추출함
  작성 중 이 목록과 코드가 다르면 코드를 기준으로 쓰고 나에게 알린다.
- 실험 결과 수치, 사용자 평가 결과, 통계, 참고문헌을 지어내지 않는다.
  - 데이터가 없으면 [TODO: 필요한 데이터 설명] 자리표시를 넣는다.
  - 근거가 필요한 주장에는 [인용 필요: 필요한 근거]를 넣는다. 내가 제공한 참고문헌만 인용한다.

[그림·표·각주]
- 표 제목은 표 위에 "[표 N] 제목", 그림 제목은 그림 아래에 "[그림 N] 제목"으로 쓴다. 번호는 논문 전체에서 1부터 차례로 매긴다. 학과 관례가 다르면 그것을 따른다.
- 모든 그림과 표는 본문에서 먼저 언급한 뒤 배치한다. (예: "[그림 3]과 같이")
- 그림은 직접 만들 수 없으므로 [그림 N 삽입: 내용 설명 / 자료 종류(구조도, ERD, 화면 캡처 등)] 자리표시를 넣는다. 구조도와 흐름도는 Mermaid 초안을 함께 제시해도 된다.
- 코드는 길게 붙이지 않는다. 핵심 로직은 의사코드나 10줄 이내 발췌로 보이고, 긴 프롬프트와 API 명세는 부록으로 보낸다.
- 각주는 마크다운 각주([^1])로 표시한다. 한글(hwp)로 옮길 때 9pt 각주로 바꾼다.

[출력]
- 장마다 docs/thesis/ 아래 별도 파일로 저장한다. (예: docs/thesis/ch3-design.md)
- 글꼴, 글자 크기, 줄간격, 여백은 한글(hwp)에서 적용하므로 마크다운에서는 신경 쓰지 않는다. 대신 한글에 붙여 넣기 쉽도록 제목, 문단, 표 구조를 깔끔하게 유지한다.
- 코드 파일은 수정하지 않는다.
- 한 장을 끝낼 때마다 채팅으로 다음을 보고한다: 근거로 삼은 파일 목록, 남긴 TODO와 인용 필요 목록, 목차와 달라진 점.

참고 문서를 먼저 읽고, 작성에 들어가기 전에 확인이 필요한 점이 있으면 질문하라.
````

## 3. 최종 검수 프롬프트

## 4. 한글(hwp)로 옮길 때 확인할 것

프롬프트로 만든 원고는 내용만 담고 있으므로 서식은 한글에서 규칙대로 직접 적용한다.

- **글꼴:** 논문 전체 바탕, 논문 제목 HY견명조
- **글자 크기:** 본문 11pt, 각주 9pt, 1단
- **줄간격:** 200%
- **여백(mm):** 위 35, 머리말 0, 왼쪽 35, 오른쪽 30, 아래 25, 꼬리말 15. 표지는 좌우 여백을 같게 한다.
- **표지·내표지·인준서:** 대학원 홈페이지의 양식1·양식2 파일에 직접 입력한다. 표지 상단에 심사본은 "학위청구논문", 최종본은 "학위논문"으로 적는다.
- **사진:** 원본 색이 유지되도록 인쇄한다.

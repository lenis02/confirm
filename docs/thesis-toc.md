# 논문 목차 (초안)

> [thesis-format-rules.md](thesis-format-rules.md)에 맞춘 국문 논문 목차 초안이다.
> 제목 번호는 국문 순서 `1.` → `가.` → `1)` → `가)` → `(1)` → `(가)`를 따른다.
> 쪽 번호는 본문 조판이 끝난 뒤 채운다.

**가제:** LLM 기반 WBS 자동 생성 및 회의 어시스트 PM 에이전트 플랫폼의 설계와 구현

```text
국문초록

1. 서론
  가. 연구 배경
  나. 연구 목적
  다. 연구 범위 및 방법
  라. 논문 구성

2. 관련 연구
  가. 프로젝트 관리와 WBS
    1) WBS의 개념과 작성 원칙
    2) 작업 간 의존성과 일정 수립
  나. 회의 관리와 의사결정 추적
    1) 회의 유형별 운영 방식
    2) Action Item 관리와 미결 사항 이월
  다. 대규모 언어 모델(LLM) 기반 문서 분석
    1) 대규모 언어 모델 개요
    2) 프롬프트 엔지니어링과 구조화된 출력
  라. 기존 프로젝트 관리 도구 분석
  마. 기존 연구 및 도구의 한계와 본 연구의 차별점

3. 시스템 설계
  가. 요구사항 분석
    1) 기능 요구사항
    2) 비기능 요구사항
  나. 시스템 아키텍처
    1) 전체 구성
    2) 기술 스택
  다. 데이터베이스 설계
  라. API 설계
  마. 인증 및 보안 설계
    1) Google OAuth 2.0과 JWT 기반 인증
    2) 계정별 워크스페이스 분리와 접근 제어

4. 핵심 기능 구현
  가. WBS 자동 생성
    1) 수행계획서 업로드 및 텍스트 추출
    2) 비동기 문서 처리 흐름
    3) WBS 생성 프롬프트 설계
      가) 프로젝트 정보 추출 단계
      나) 태스크 분할 단계
      다) 의존성 기반 일정 산정 단계
    4) LLM 호출 안정화
      가) 지수 백오프 재시도
      나) 대체 모델 폴백
    5) WBS 검토·수정 및 확정
  나. WBS 기반 회의 추천
    1) 의사결정 지점 지정
    2) 회의 추천 프롬프트 설계
    3) 킥오프 회의 자동 생성
  다. 회의 어시스트
    1) 회의 유형별 체크리스트 생성
    2) 회의 브리핑과 미결 Action Item 이월
    3) 체크리스트 달성률 산출
    4) 회의록 관리
  라. 일정 시각화
  마. 사용자 인터페이스

5. 실험 및 평가
  가. 실험 환경
  나. WBS 생성 품질 평가
    1) 평가 데이터
    2) 평가 지표
    3) 결과 분석
  다. LLM 모델별 성능 비교
    1) 응답 시간
    2) 출력 형식 준수율
    3) 생성 결과 품질
  라. 사용성 평가
  마. 결과 논의

6. 결론
  가. 연구 요약
  나. 연구의 의의
  다. 한계점 및 향후 연구

참고문헌

Abstract

부록
  부록 1. WBS 생성 프롬프트 전문
  부록 2. 회의 추천 프롬프트 전문
  부록 3. API 명세
```

## 작성 시 참고

- **작성순서:** 표지 → 내표지 I → 내표지 II(인준서) 뒤에 위의 목차가 온다. 본문을 영문으로 쓰면 국문초록과 Abstract의 위치를 바꾼다.
- **그림·표 목차:** 그림과 표가 많으면 목차 바로 뒤에 `그림 목차`, `표 목차`를 두는 것을 고려한다. (규칙 문서에는 별도 언급이 없으므로 학과 관례를 확인한다.)
- **현재 코드와 맞춰 볼 부분:**
  - 4장 가-1): 현재는 OCR이 아니라 `pdf-parse`로 PDF 텍스트를 추출한다.
  - 4장 가-4): 현재 기본 모델은 Gemini(`gemini-2.5-flash`)이고 Claude 호출 코드는 주석 처리되어 있다.
  - 5장 다: 모델 비교를 하려면 Claude·GPT 호출 경로를 살리고 같은 수행계획서로 실험을 돌려야 한다.
  - 6장 다: 실시간 STT 체크리스트 검증(코드 주석 처리), Naver Works·Notion 연동(API 비활성화)은 미구현이므로 향후 연구로 다룬다.
